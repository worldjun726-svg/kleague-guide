# 개인정보 보안 점검표

마지막 점검: 2026-11-22

회원 정보(이메일, 닉네임, 카카오·Google 정보)는 모두 Supabase에 저장되고, 사이트 코드에는 공개용 키(publishable)만 들어 있습니다.
**관리자 열쇠는 결국 "Supabase·카카오·Google·GitHub 계정"이므로, 이 계정들을 지키는 것이 가장 중요합니다.**

## 1. 지금 바로 할 일

### 1-1. 보안 강화 SQL 실행 (사이트 배포 전에)
Supabase → **SQL Editor → New query** → `supabase/security-hardening.sql` 내용을 통째로 붙여 넣고 **Run**.

이 파일이 하는 일:
| 문제 | 바뀐 점 |
|---|---|
| 응원 글 작성자 이름을 브라우저가 보내서, 남의 닉네임을 쓰거나 이메일 앞부분이 공개될 수 있었음 | 서버가 프로필 닉네임으로 채움. 가입 마무리(닉네임·약관 동의)를 한 회원만 글쓰기 가능. 이미 올라간 글의 이름도 정리 |
| 로그인하지 않은 사람도 모든 회원의 회원 ID·경기 예측을 내려받을 수 있었음 | 예측은 본인만 보고, 다른 사람에게는 집계 숫자만(`prediction_counts`) |
| 회원 탈퇴 기능이 없었음 | `delete_my_account` 추가 → 내 페이지 → 내 정보 → **회원 탈퇴** |
| 내부용 함수를 사이트에서 직접 부를 수 있었음 | 실행 권한 회수 |
| 회원 명단을 볼 곳이 마땅치 않았음 | 관리자 전용 `admin.members` (사이트에서는 접근 불가) |

### 1-2. 계정 2단계 인증 (가장 중요)
회원 명단은 이 계정들로만 볼 수 있습니다. 비밀번호가 새면 명단 전체가 새므로 모두 2단계 인증을 켜세요.
- [ ] **Supabase** 계정: 오른쪽 위 프로필 → Account preferences → **Multi-factor authentication**
- [ ] **GitHub** 계정: Settings → Password and authentication → **Two-factor authentication** (사이트 코드·배포 권한)
- [ ] **카카오** 계정: 카카오계정 → 계정 보안 → **2단계 인증**
- [ ] **Google** 계정: Google 계정 → 보안 → **2단계 인증**

### 1-3. Supabase 인증 설정 (Authentication 메뉴)
- [ ] **URL Configuration**
  - Site URL: `https://worldjun726-svg.github.io/kleague-guide/`
  - Redirect URLs: 사이트 주소만 정확히 적기(`https://worldjun726-svg.github.io/kleague-guide/`). `*`나 `**` 같은 와일드카드는 쓰지 않기 — 로그인 후 엉뚱한 사이트로 토큰이 넘어가는 것을 막습니다.
  - 로컬 확인용 `http://localhost:…` 주소는 쓸 때만 잠깐 넣고 지우기
- [ ] **Sign In / Providers → Email**: Confirm email **ON**, Secure email change **ON**, Secure password change **ON**
- [ ] **비밀번호 규칙**(Sign In / Providers → Email 또는 Policies): 최소 길이 **8**, 문자 조건 **영문 대소문자+숫자** 이상
- [ ] **Rate Limits**: 기본값 유지(낮추는 것은 괜찮고, 올리지 않기)
- [ ] (선택) **Attack Protection → CAPTCHA**(Cloudflare Turnstile): 가입 도배가 생기면 켜기 — 사이트 코드도 함께 고쳐야 하므로 필요할 때 요청

### 1-4. Supabase 보안 점검 도구
- [ ] **Advisors → Security Advisor**를 열어 경고(빨간색/주황색)가 있는지 확인. SQL 실행 후 한 번, 이후 표를 새로 만들 때마다 확인
- [ ] **Project Settings → Data API → Exposed schemas**에 `public`, `graphql_public`만 있는지 확인 (**`admin`을 넣으면 안 됨**)
- [ ] **Project Settings → API Keys**: 사이트에는 `sb_publishable_…`만 씀. `sb_secret_…`/service_role 키는 어디에도 붙여 넣지 않기. 새어 나간 의심이 들면 그 화면에서 바로 새로 발급(Rotate)

## 1-5. 직관 동행·양도 (supabase/meetup.sql)
- SQL Editor 에서 `supabase/meetup.sql` 실행(Realtime 등록 포함). 실행 후 Database → Publications → supabase_realtime 에 meet_messages·meet_requests 가 있는지 확인
- 권한: 글은 누구나 읽기 / 신청은 신청자·글쓴이만 / 1:1 대화는 수락된 두 사람만(RLS, Realtime 에도 그대로 적용) / 신고 내용은 관리자만
- 제한: 글 하루 5개, 신청 1시간 10번, 메시지 1분 20개, 차단 시 신청·대화 불가, 3명 이상 신고된 글 자동 숨김
- 양도는 정가 이하만(DB 제약 `ask_price <= face_price`). 사이트에서 돈을 주고받지 않음
- 신고 확인: `select * from admin.meet_reports_view;` → 문제 글 숨기기 `update public.meet_posts set hidden = true where id = <번호>;`
- `public.member_names` 뷰는 닉네임만 공개(이메일 등 비공개). Security Advisor 가 '보안 정의자 뷰'로 표시할 수 있으나 의도한 것

## 2. 회원 명단 보는 법 (관리자만)
- Supabase → **SQL Editor** → `select * from admin.members;`
- 또는 **Table Editor** 왼쪽 위 schema를 `admin`으로 바꾸고 `members`
- 가입일, 가입 방식(email·kakao·google), 이메일, 닉네임, MY 팀, 약관·마케팅 동의, 이메일 인증, 마지막 로그인이 보입니다.
- 로그인 기록은 **Authentication → Logs**(Auth 로그)에서 확인

### 명단 다룰 때 지킬 것
- 명단은 **대시보드 안에서만** 보기. 캡처·CSV 내려받기는 꼭 필요할 때만 하고, 쓴 뒤 바로 지우기(휴지통도 비우기)
- 카카오톡·메일·클라우드 드라이브로 명단을 보내지 않기
- 회원에게 소식 메일을 보낼 때는 `마케팅동의 = true`인 사람에게만 (정보통신망법)
- 사이트에 "관리자 화면"을 따로 만들지 않기 — 필요하면 별도 설계

## 3. 이미 안전하게 되어 있는 것 (점검 결과)
- 사이트 코드·배포본·저장소 기록에 Supabase 관리자 키(service_role / `sb_secret_`) 없음
- 로그인은 PKCE 방식(`src/accountApi.ts`) — 로그인 코드가 가로채져도 다른 곳에서 쓸 수 없음
- 비밀번호는 Supabase가 암호화(해시)해서 저장하고, 사이트·관리자 모두 원문을 볼 수 없음
- `profiles`·`favorites`: 본인 것만 보고 고칠 수 있음(RLS)
- 응원 글: 본인 글만 지울 수 있고, 1분에 5개 넘게 못 씀
- 닉네임 중복 확인 함수는 "있다/없다"만 돌려주고 다른 회원 정보는 주지 않음
- 실시간 점수 Edge Function(`kleaguelive`)은 공개 경기 자료만 다루고 회원 정보에 접근하지 않음
- 카카오 로그인은 동의항목 최소(닉네임 필수, 프로필 사진·이메일 선택)

## 4. 남은 위험 / 나중에 할 것
- **저장소 과거 기록의 `config/secret_key`, `config/field_encryption_key`**: 사이트와 무관한 Codex 앱 설정이지만 공개 저장소의 커밋 기록(`b9ed515`, `a79ff30`)에 남아 있어 누구나 볼 수 있음. 그 앱을 계속 쓴다면 두 키를 새로 만들어야 함. 기록에서 지우려면 강제 push로 기록을 다시 써야 함(되돌릴 수 없는 작업이라 결정 필요)
- **개인정보처리방침 확정**(`#/privacy`, `src/Legal.tsx`): 운영자 이름·연락처, 개인정보 보호책임자, Supabase 서버 위치(Project Settings → General의 Region)에 따른 **국외 이전** 고지, Google(미국) 고지가 필요
- **경기 예측 시작 시각**: 예측의 경기 시작 시각을 브라우저가 보내므로, 마음먹으면 끝난 경기에 예측을 넣어 적중률을 부풀릴 수 있음(개인정보 문제는 아님). 필요하면 서버에 경기 일정 표를 두고 검사
- 카카오 탈퇴 시 카카오 쪽 연결 끊기(unlink)는 아직 하지 않음 — 카카오 계정 설정 → 연결된 서비스에서 사용자가 직접 끊을 수 있음
